## Блок 1: Регистры и пересылка данных 

Прежде чем считать, процессору нужно знать, **где** лежат данные. В x86-64 основные 64-битные регистры общего назначения: `rax`, `rbx`, `rcx`, `rdx`, `rsi`, `rdi`, `r8`-`r15`.
*(32-битные "младшие" части: `eax`, `ebx` и т.д.)*

### Инструкция `mov` (Move)
Это не перемещение, а **копирование**. `mov приёмник, источник`.

**Код на C:**
```c
void copy_data(long a, long b) {
    long x = a;
    long y = b;
    long z = x;
}
```

**Ассемблер (x86-64):**
```asm
copy_data:
        mov     rax, rdi      ; x = a (rdi - 1-й аргумент)
        mov     rdx, rsi      ; y = b (rsi - 2-й аргумент)
        ret                   ; z = x (rax - регистр возврата)
```
*Системная заметка:* Компилятор даже не создал переменные `x`, `y`, `z` в памяти. Он просто переназначил регистры. Это называется **Register Allocation**.

### Инструкция `lea` (Load Effective Address)
**Самая важная инструкция для системщика.** Она вычисляет адрес памяти, но **не обращается к памяти**. Фактически, это скрытый арифметический блок.

### Контекст: Откуда берутся регистры?

Прежде чем смотреть на инструкции, вспомним **Calling Convention** (соглашение о вызовах). Как функция понимает, где её аргументы?

*   **В x86-64 (System V ABI, стандарт для Linux/macOS):** 
    Первые 6 целочисленных аргументов передаются в регистрах: `rdi`, `rsi`, `rdx`, `rcx`, `r8`, `r9`. 
    Возвращаемое значение кладется в `rax`.
    *Функция:* `base` попадает в `rdi`, `index` попадает в `rsi`.
*   **В ARM64 (AAPCS):** 
    Первые 8 целочисленных аргументов передаются в регистрах `x0` – `x7`. 
    Возвращаемое значение кладется в `x0`.
    *Наша функция:* `base` попадает в `x0`, `index` попадает в `x1`.

### 2. Глубокий разбор x86-64: Инструкции `lea`

```c
long calc_addr(long base, long index) {
    return base + index * 8 + 16;
}
```
```asm
calc_addr:
        lea     rax, [rdi + rsi*8 + 16]
        ret
```

#### Что такое `lea` на самом деле?
`lea` расшифровывается как **Load Effective Address** (Загрузить эффективный адрес). 
Её *прямое* назначение: вычислить адрес ячейки памяти, но **не читать и не писать** в эту память. Просто положить вычисленный адрес в регистр.

#### Формула адресации x86-64
Аппаратура x86 имеет специальную формулу для вычисления адресов памяти, которая выглядит так:
`[Базовый_регистр + Индексный_регистр * Масштаб + Смещение]`

Где:
*   **Базовый регистр:** любой регистр общего назначения (у нас `rdi` = `base`).
*   **Индексный регистр:** любой регистр (у нас `rsi` = `index`).
*   **Масштаб (Scale):** жестко ограничен значениями **1, 2, 4 или 8**. (Почему 8? Потому что это размер `long` или указателя в 64-битной системе, и процессор оптимизирован под работу с массивами таких элементов).
*   **Смещение (Displacement):** константа от -128 до +127 (или 32-битная в некоторых режимах). У нас `16`.

#### Почему это гениально и быстро?
В процессоре есть два разных вычислительных блока:
1.  **ALU (Arithmetic Logic Unit):** выполняет `add`, `sub`, `imul`.
2.  **AGU (Address Generation Unit):** вычисляет адреса для доступа к памяти.

Когда компилятор видит `base + index * 8 + 16`, он понимает: "Формула адресации x86!". 
Вместо того чтобы:
1. Загрузить `imul` в ALU (умножение `rsi` на 8, это ~3 такта).
2. Загрузить `add` в ALU (сложение с `rdi`, 1 такт).
3. Загрузить еще один `add` в ALU (сложение с 16, 1 такт).

...он скармливает всё это **одной инструкцией `lea`** в блок **AGU**. 
**Результат:** Вычисление происходит за **1 такт**, при этом основной блок ALU остается свободным и может параллельно выполнять другие инструкции вашей программы (это называется *Instruction Level Parallelism*).

### 3. Глубокий разбор ARM64: Философия RISC и Barrel Shifter

ARM(Мобильная архитектура) — это архитектура **RISC** (Reduced Instruction Set Computer). У неё строгие правила:
1. Все инструкции имеют фиксированную длину (32 бита).
2. Нельзя делать сложные вычисления внутри обращения к памяти.
3. Большинство инструкций имеют формат: `Операция Приемник, Источник1, Источник2`.

Поэтому в ARM **нет** аналога `lea` с такой сложной формулой. Но ARM компенсирует это другой гениальной аппаратной фичей: **Barrel Shifter** (циклический сдвигатель), встроенный прямо на вход ALU.

```asm
// x86: lea rax, [rdi + rsi*8 + 16]
// ARM64:
add x0, x0, x1, lsl #3   // Шаг 1
add x0, x0, #16          // Шаг 2
```

#### Разбор Шага 1: `add x0, x0, x1, lsl #3`
*   `add`: операция сложения.
*   `x0` (первый): регистр-приемник (сюда запишем результат).
*   `x0` (второй): первый источник. В нем лежит наш `base`.
*   `x1, lsl #3`: второй источник. В `x1` лежит `index`. Но перед тем как попасть в сумматор, значение `x1` проходит через **Barrel Shifter** и сдвигается влево (Logical Shift Left) на 3 бита.

**Почему сдвиг влево на 3 = умножению на 8?**
В двоичной системе каждый сдвиг влево умножает число на 2.
*   Сдвиг на 1: `* 2`
*   Сдвиг на 2: `* 4`
*   Сдвиг на 3: `* 8`

**Главный секрет ARM:** Применение сдвига (`lsl #3`) во время выполнения `add` **не стоит дополнительных тактов**. Это делается аппаратно "бесплатно" за тот же 1 такт, что и обычное сложение.

#### Разбор Шага 2: `add x0, x0, #16`
*   Теперь в `x0` лежит результат `base + (index * 8)`.
*   Мы просто добавляем к нему константу `16`.
*   ARM позволяет встраивать небольшие константы (до 12 бит, т.е. 0–4095) прямо в машинный код инструкции `add`, поэтому отдельная загрузка константы в регистр не требуется.

### 4. Сравнительная таблица подходов

| Характеристика | x86-64 (CISC) | ARM64 (RISC) |
| :--- | :--- | :--- |
| **Количество инструкций** | 1 (`lea`) | 2 (`add` + `add`) |
| **Используемый блок CPU** | AGU (Address Generation Unit) | ALU + встроенный Barrel Shifter |
| **Затраты тактов** | 1 такт | 2 такта (но конвейер часто выполняет их параллельно) |
| **Гибкость** | Жесткая: множитель только 1, 2, 4, 8 | Высокая: можно сдвигать на любое число от 0 до 63 |
| **Читаемость** | Выглядит как работа с памятью, но это математика | Выглядит как чистая математика, прозрачно и предсказуемо |

## Блок 2: Арифметические операции 

### Сложение и вычитание
`add приёмник, источник` и `sub приёмник, источник`.

**Код на C:**
```c
long add_sub(long a, long b) {
    return (a + 10) - (b - 5);
}
```

**Ассемблер:**
```asm
add_sub:
        lea     rax, [rdi + 10]   ; rax = a + 10
        lea     rdx, [rsi - 5]    ; rdx = b - 5
        sub     rax, rdx          ; rax = rax - rdx
        ret
```

### Умножение и деление
В x86 деление и умножение исторически используют **скрытые регистры**.

**Код на C:**
```c
long math_ops(long a, long b) {
    long prod = a * b;
    long quot = a / b;
    return prod + quot;
}
```

**Ассемблер:**
```asm
math_ops:
        mov     rax, rdi
        imul    rax, rsi          ; prod = a * b (результат в rax)
        mov     r8, rax           ; сохраняем prod в r8
        
        mov     rax, rdi          ; готовим делимое
        cqo                       ; расширяем знак rax в rdx:rax (КРИТИЧНО!)
        idiv    rsi               ; quot = rdx:rax / rsi. Частное в rax, остаток в rdx
        
        add     rax, r8           ; возвращаем prod + quot
        ret
```
**Системная ловушка:** Инструкция `idiv` делит **128-битное** число `rdx:rax` на `rsi`. Если перед `idiv` не очистить/расширить `rdx` (инструкцией `cqo` для знаковых или `xor edx, edx` для беззнаковых), программа упадет с ошибкой **Floating-point exception** (да, в x86 деление на ноль или переполнение деления вызывает SIGFPE).

### ARM64 эквиваленты
В ARM64 нет скрытых регистров для умножения/деления.
```asm
// Умножение
mul x0, x0, x1

// Деление
sdiv x0, x0, x1  (знаковое)
udiv x0, x0, x1  (беззнаковое)
```

##  Блок 3: Логические и побитовые операции

`and`, `or`, `xor`, `not`. А также сдвиги: `shl` (влево), `shr` (вправо логический), `sar` (вправо арифметический).

### Трюк обнуления регистра
**Код на C:**
```c
long zero_and_shift(long a) {
    long b = 0;
    long c = a >> 2; // Деление на 4
    return b + c;
}
```

**Ассемблер:**
```asm
zero_and_shift:
        xor     eax, eax        ; Обнуление eax (быстрее и короче, чем mov eax, 0)
        mov     rdx, rdi
        sar     rdx, 2          ; Арифметический сдвиг вправо (сохраняет знак!)
        lea     rax, [rdx + rax]
        ret
```
*Системная заметка:* `xor eax, eax` занимает 2 байта, `mov eax, 0` — 5 байт. Кроме того, `xor` сбрасывает зависимости от предыдущего значения регистра в конвейере CPU (dependency breaking).

### Побитовые маски
**Код на C:**
```c
long bit_ops(long a, long b) {
    return (a & 0xFF) | (b << 4);
}
```

**Ассемблер:**
```asm
bit_ops:
        and     edi, 255        ; a & 0xFF (255 = 0xFF)
        shl     rsi, 4          ; b << 4
        or      rax, rsi        ; (в rax уже лежит edi, т.к. это регистр возврата)
        ret
```

## Блок 4: Разный компилятор - разные инструкции. GCC vs Clang 

*Ассемблер — это не один язык, а целое семейство. Нельзя просто сказать «я пишу на ассемблере». Под каждый процессор (для компьютера, телефона или микроволновки) существует свой собственный ассемблер со своими командами.Компиляторы действуют как переводчики. 
Представьте, что два человека переводят одну фразу с английского на русский. Один переведет её строго по словарю, а второй — разговорным языком. Смысл останется прежним, но текст будет разным. Точно так же компиляторы переводят ваш код на язык процессора.*


**Вставьте этот код в Godbolt:**
```c
int complex_calc(int a, int b, int c) {
    int sum = a + b + c;
    int avg = sum / 3;
    int rem = sum % 3;
    return avg * 2 + rem;
}
```

### GCC 14.1 (-O2)
```asm
complex_calc:
        lea     eax, [rdi+rsi]
        add     eax, edx
        mov     ecx, eax
        sar     ecx, 31         ; Извлечение знака для корректного деления отриц. чисел
        shr     ecx, 30         ; Сдвиг для получения магического числа делителя
        add     ecx, eax        ; Деление через умножение на магическое число!
        sar     ecx, 1
        lea     edx, [rcx+rcx]
        sub     eax, edx        ; Вычисление остатка (rem)
        lea     eax, [rcx+rdx]  ; avg * 2 + rem
        ret
```

### Clang 18.1 (-O2)
```asm
complex_calc:
        lea     eax, [rdi + rsi + rdx]  ; Сумма одной инструкцией!
        mov     ecx, eax
        sar     ecx, 31
        shr     ecx, 30
        add     ecx, eax
        sar     ecx
        lea     edx, [rcx + rcx]
        sub     eax, edx
        lea     eax, [rdx + rcx]
        ret
```

### Анализ различий:
1. **Сложение:** Clang использовал `lea eax, [rdi + rsi + rdx]`, сложив три регистра одной инструкцией. GCC сделал это в два шага (`lea` + `add`).
2. **Деление на константу:** Оба компилятора **не использовали** инструкцию `idiv`! Деление на константу (3) очень медленное. Компиляторы заменяют его на умножение на "магическое число" и сдвиги (`shr`, `sar`). Это классическая оптимизация "Division by Invariant Multiplication" (алгоритм Гранлунда-Монтгомери).
3. **Финальное сложение:** GCC и Clang по-разному распределили регистры в последних строках `lea`, но результат математически идентичен.
